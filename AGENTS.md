Friend-group display order is persisted in `friend_groups.sort_order`; all group consumers use the RPC order so personal ordering stays consistent.
- Round bet-config edits use a serialized, atomic three-way merge keyed by unordered player pair and bet type; rebase realtime state so concurrent phones cannot discard bilateral amounts.
- Handicap ranking RPCs compute differentials with `_adjusted_gross_score` (Net Double Bogey, same stroke allocation as `calculateStrokesPerHole`); keep both in sync so rankings match the in-app Handicap Index.
- League player history reads gross and net totals from leaderboard_scores; constrain ScrollArea content and use fixed table columns so horizontal player selectors cannot widen the page.
- Bloques final-block pressure uses the existing pair-keyed multiplier and one shared switch in both bilateral detail views, so calculation and atomic round persistence stay consistent.
- Cross bets render as a synthetic `cross:<id>` rival avatar whose BilateralDetail is fed by `buildCrossVirtualRound`; never add the crossed friend to round players or the balance map, so crossings stay isolated and counted once.
- Snapshot saves recover transport failures by reading back the exact attempt's timestamp and version; never accept an older snapshot or repeat financial writes to recover a lost response.
- Historical round snapshots remain immutable for intra-round bets; add cross-card settlement records separately from the authenticated own-history RPC, deduplicate by ledger ID, and never increase played-round counts for a crossing.
- Oyes pools and carry are isolated by player group; Medal General respects group/global/both scope in the shared engine and is never recalculated in synthetic cross-group pairs, so live and closing totals agree.
- All group player removals share a verified persistence callback; update local players, score maps and ID aliases only after a returned deleted row, so failed or denied removals cannot masquerade as success.
- Round close blocks when any player lacks confirmed real scores on active holes (findMissingCloseHoles) and never promotes placeholder par scores to confirmed, so removed or unplayed players cannot generate fictitious balances.
- Carritos "Medal por Parejas" (scoringMethod 'strokes') is computed only by computeCarritosStrokesResult, shared by the engine and BetDashboard, and reuses the 'Carritos Front/Back/Total' betTypes so snapshot team-bet exclusions and Medal overrides keep working.
- Carritos setup generators and duplicate checks key each match by its 4 players plus scoringMethod (absent = 'points'), so a Carritos and a Medal por Parejas between the same players coexist and generation/shuffle never drops the type.
- Carritos result cards switch to stroke totals only when results.method === 'strokes'; legacy primary Carritos is disabled as `carritos-primary-<idx>` while its ledger betId stays `carritos-<idx>`, so ledger emission must honour both ids.
- Only Auth is eagerly bundled in App.tsx; every other page (including Index) is a lazy route chunk, and Index is prefetched when a stored session exists, so first-time visitors on slow phones see sign-in without downloading the round screen.
- Sentry beforeSend rewrites plain-object rejections ({ code, message, … }) via normalizeSentryEvent into readable titles tagged by error_code, so backend failures are identifiable instead of "Object captured as promise rejection".
