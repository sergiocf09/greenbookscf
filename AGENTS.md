- Round bet-config edits use a serialized, atomic three-way merge keyed by unordered player pair and bet type (and by event id for `events` lists such as Zoológico, client and server alike); rebase realtime state so concurrent phones cannot discard bilateral amounts.
- Handicap ranking RPCs compute differentials with `_adjusted_gross_score` (Net Double Bogey, same stroke allocation as `calculateStrokesPerHole`); keep both in sync so rankings match the in-app Handicap Index.
- League player history reads gross and net totals from leaderboard_scores; constrain ScrollArea content and use fixed table columns so horizontal player selectors cannot widen the page.
- Bloques final-block pressure uses the existing pair-keyed multiplier and one shared switch in both bilateral detail views, so calculation and atomic round persistence stay consistent.
- Cross bets render as a synthetic `cross:<id>` rival avatar whose BilateralDetail is fed by `buildCrossVirtualRound`; never add the crossed friend to round players or the balance map, so crossings stay isolated and counted once.
- Snapshot saves recover transport failures by reading back the exact attempt's timestamp and version; never accept an older snapshot or repeat financial writes to recover a lost response.
- Historical round snapshots remain immutable for intra-round bets; add cross-card settlement records separately from the authenticated own-history RPC, deduplicate by ledger ID, and never increase played-round counts for a crossing.
- Oyes pools and carry are isolated by player group; Medal General respects group/global/both scope in the shared engine and is never recalculated in synthetic cross-group pairs, so live and closing totals agree.
- All group player removals share a verified persistence callback; update local players, score maps and ID aliases only after a returned deleted row, so failed or denied removals cannot masquerade as success.
- Round close blocks when any player lacks confirmed real scores on active holes (findMissingCloseHoles) and never promotes placeholder par scores to confirmed, so removed or unplayed players cannot generate fictitious balances.
- Carritos "Medal por Parejas" (scoringMethod 'strokes') is computed only by computeCarritosStrokesResult, shared by the engine and BetDashboard, and reuses the 'Carritos Front/Back/Total' betTypes so snapshot team-bet exclusions and Medal overrides keep working.
- Carritos setup generators and duplicate checks key each match by its 4 players plus scoringMethod (absent = 'points'), so a Carritos and a Medal por Parejas between the same players coexist and generation/shuffle never drops the type.
- Carritos result cards switch to stroke totals only when results.method === 'strokes'; legacy primary Carritos is disabled as `carritos-primary-<idx>` while its ledger betId stays `carritos-<idx>`, so ledger emission must honour both ids.
- Only Auth is eagerly bundled in App.tsx; every other page (including Index) is a lazy route chunk, and Index is prefetched when a stored session exists, so first-time visitors on slow phones see sign-in without downloading the round screen.
- Sentry beforeSend rewrites plain-object rejections ({ code, message, … }) via normalizeSentryEvent into readable titles tagged by error_code, so backend failures are identifiable instead of "Object captured as promise rejection".
- Tablet enlargement uses the `tab:` Tailwind screen and `tab-zoom-*` CSS zoom classes (same ≥768px wide, ≥600px tall query) and PopoverContent/TooltipContent stay portaled, so phones stay untouched and zoom never compounds or breaks popover positioning.
- `merge_round_bet_config` lets only the organizer and G1 co-admins change base round bets; G2+ players and G2+ co-admins may change only their own `groupBetOverrides` entry (co-admins keep dashboard edits), raising ROUND_ADMIN_REQUIRED otherwise; in BetSetup's "Mi grupo" tab whole-config edits go through `applyConfigChangeForGroup` (object bets become group overrides; team-bet lists stay in the base list via `mergeGroupScopedList`, because their engines read the base config and entries are scoped by players), so a secondary group can never rewrite the inherited G1 config or another group's bets.
- Pending rounds auto-restore only when dated today/yesterday (`pickAutoRestoreRoundId`) and scored setup rounds idle 48h close as incomplete without balances, so forgotten rounds never silently become a player's current round.
- Leaderboard prizes live in their own `leaderboard_prizes` row (never in `rules_json`) and are computed only by the pure `computePrizePayouts` engine in cents, so standings stay untouched and splits are exact.
- Prize Oyes slots use deterministic ids (`oyes-d{day|0}-h{hole}`) and are merged only by id (`mergeGeneratedSlots`), so regenerating never duplicates or overwrites the organizer's amounts and winners.
- Multi-winner special awards store each extra place as its own SpecialAward (`${baseId}-p${n}`, `groupId`, `place`, derived label) via the pure helpers in `src/lib/prizeSlots.ts`, so the payout engine, panel, share image and frozen snapshot need no changes.
- Prize views show draft/live payouts from the `prizeCandidates` projection adapter (every confirmed hole so far, provisional) and freeze only with the strict adapter (completed expected holes); a 'final' status renders only the stored `FinalPayoutsSnapshot` with frozen names, so live prizes follow the round but frozen prizes never change with later scores or handicaps.
- Prize share images and the historical prizes card read a 'final' result only through `sharePayoutsFromSnapshot` (frozen names, every paid place per pool); live shares reshape the strict PrizesPanel result via `buildPrizesSharePayouts`, so shared images never trigger a recalculation of frozen prizes.
- The Prizes panel groups special awards for display only via `buildAwardDisplaySections` (first label segment = section, extra places resolved by groupId or the `-p<n>` id for frozen snapshots), so presentation never alters amounts or winners.
- The Stableford hole-by-hole grid lives only in `StablefordHoleDetail` (group bet popover and leaderboard tables), so both views always look and colour points the same.
- Prize winner HCP/result columns and the per-player summary chips come only from the pure helpers in `src/lib/prizeResultStats.ts`; a 'final' status reads HCP/results frozen into `FinalPayoutsSnapshot.participants` (hidden for older snapshots), so frozen prizes never show later scores.
- Historical Balances adds tournament winnings only from frozen `leaderboard_prizes.final_payouts` via `src/lib/tournamentWinnings.ts` (never entry fees, never recalculated), shown as one expandable "Torneos" row and counted in Vs Rivales Balance Total, so prize money stays separate from round snapshots.
- Prize screens and share images show whole pesos only through `roundPayoutForDisplay` (largest remainder per pool, player totals re-summed from rounded rows); the engine and frozen snapshots keep exact cents, so display rounding never alters stored payouts or totals.
- Player stats/achievement RPCs (get_player_stats, get_player_milestones, get_player_recent_rounds, get_player_courses_summary, get_player_score_by_hole) and any highlights/email stats count only the played segment of 9-hole rounds (bet_config.roundHoles=9 + starting_hole) and exclude them from 18-hole totals, so placeholder pars from the unplayed nine never inflate best rounds or hole counts.
- Highlights campaigns are built by `docs/email/highlights-tools` (stats + per-player adaptive HTML) and sent through a temporary owner-gated edge function that is deleted after the send; message_id `<campaign>-<profile_id>` is checked against email_send_log so a re-run never emails anyone twice.
- Cross-group pair settlement (dashboard and close engine) uses `stripTeamBetsForCrossPair` + `keepCrossPairSummaries`, since team-bet engines ignore the player list and would leak other players' bets into the pair.
